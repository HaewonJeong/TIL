1. 로그인 폼 받기 — `/login`

### 뭘 하는 거냐면

사용자가 아이디랑 비밀번호를 입력해서 보내면, 서버가 그걸 받아주는 코드예요.

```python
async def login(username, password):
    return {"username": username, "authenticated": bool(password)}
```

- 아이디는 **2글자 이상**, 비밀번호는 **8글자 이상**이어야 통과돼요. 짧으면 FastAPI가 알아서 "안 됨"이라고 튕겨줘요. (우리가 따로 if문 안 짜도 됨!)
- 진짜 로그인 검증(비번이 맞는지)은 안 하고, 여기선 그냥 "값을 잘 받았는지"만 연습한 거예요.

## 2. 파일 올리고 검사만 해보기 — `/files`

### 비유로 설명하면

택배 접수 창구를 생각하면 쉬워요. 손님이 상자(파일)랑 메모(설명)를 같이 가져와요. 직원(서버)은 상자를 열어보지 않고도 **"이거 무슨 상자냐, 크기가 얼마냐"**만 확인해줘요.

```python
if content_type not in 허용목록:
    "text 또는 pdf만 허용합니다"  # 에러

if 파일크기 > 1MB:
    "파일은 1MB 이하여야 합니다"  # 에러
```

- **타입 검사**: txt, pdf 파일만 받고 나머지(이미지, 실행파일 등)는 다 거절해요.
- **크기 검사**: 1MB보다 크면 거절해요. 근데 여기서 재밌는 포인트는, 서버가 파일을 **"1MB + 1바이트"만큼만** 살짝 찍어보고 "어 이거 넘네" 하고 바로 멈춘다는 거예요. 굳이 100MB짜리 파일을 끝까지 다 읽고 나서 "너무 크네요" 하면 시간 낭비니까, **살짝만 보고 빨리 판단**하는 거죠.
- 이 API는 저장은 안 하고 "검사만" 해줘요. 진짜 저장은 다음 단계에서요.

## 3. 파일 진짜로 저장하기 — `/api/v1/files`

### 비유로 설명하면

이번엔 택배를 실제로 **창고에 넣고 송장 번호를 붙이는** 단계예요.

**① 이중 검사**

```python
{"text/plain": ".txt", "application/pdf": ".pdf"}
```

파일이 "나 pdf임" 하고 우겨도, 실제 파일 이름 끝이 `.pdf`가 아니면 튕겨내요. 이름표(content_type)만 믿지 않고 **겉모습(확장자)까지 같이 확인**하는 거예요. 신분증이랑 얼굴을 같이 확인하는 것과 비슷해요.

**② 이름을 바꿔서 저장**

```python
file_id = 새로운_고유번호()
저장이름 = f"{file_id}.pdf"
```

사람들이 파일 이름을 `이력서.pdf`, `이력서(1).pdf`, `이력서_최종.pdf` 이렇게 제각각으로 올려도, 서버는 그걸 그대로 안 쓰고 **완전히 새로운 이름(고유번호)**을 붙여서 저장해요. 그래야:

- 이름이 겹쳐서 남의 파일을 덮어쓰는 사고가 안 나고
- 이상한 문자가 섞인 파일명 때문에 생기는 오류도 막을 수 있어요.

**③ 송장(메타데이터) 따로 보관**

```python
{원래이름, 저장이름, 설명, 크기 ...} → JSON 파일로 저장
```

실제 파일(내용물)이랑, "이게 원래 이름이 뭐였고 언제 뭔 설명이랑 같이 왔는지" 적어둔 **메모(JSON)**를 따로 저장해요. 택배 상자엔 번호만 붙어있고, 그 번호에 대한 자세한 정보는 창구 컴퓨터 장부에 적어두는 것과 같아요.

UUID(file_id)  # 이 번호가 진짜 형식이 맞는지 확인

누가 이상한 값(`../../비밀파일` 같은 것)을 파일 번호인 척 보내면, 서버가 "이거 번호 형식이 아니잖아" 하고 **바로 거절**해요. 엉뚱한 값으로 서버 안의 다른 파일에 접근하려는 시도를 막아주는 안전장치예요.
