## 1. FastAPI 시작하기 (`01_start/main.py`)

### 비유로 이해하기

FastAPI 앱은 **"손님이 문을 두드리면 정해둔 직원이 응대하는 가게"**라고 생각하면 쉬워요. `@app.get("/")`처럼 주소(문)를 정해두고, 그 아래 함수가 "이 문으로 오면 이렇게 응대해라"는 규칙이에요.

```python
@app.get("/", tags=["start"])
async def root2() -> dict[str, str]:
    return {"message": "Hello FastAPI"}
```

- 파이썬 딕셔너리(`dict`)를 그냥 리턴하면 FastAPI가 알아서 JSON으로 바꿔서 손님에게 보내줘요.
- `@app.post("/echo")`처럼 **GET 전용 주소에 POST로 요청하면 405 에러**가 나요. "이 문은 들어오는 문이지 나가는 문이 아니에요" 하고 막는 것과 비슷해요.

### 동기(sync) vs 비동기(async) — 제일 재밌는 부분

```python
@app.get("/wait/sync")
def sync_wait(seconds=1):
    time.sleep(seconds)   # 여기서 가게 전체가 멈춤

@app.get("/wait/async")
async def sync_wait(seconds=1):
    await asyncio.sleep(seconds)  # 나만 잠깐 쉬고, 가게는 계속 돌아감
```

- **동기(`time.sleep`)**: 직원 한 명이 손님 응대하다가 잠깐 자리를 비우면, 그동안 **다른 손님도 전부 기다려야** 해요.
- **비동기(`asyncio.sleep`)**: 직원이 "이 손님은 잠깐 기다리는 중이에요" 표시만 해두고, **그 사이에 다른 손님을 먼저 응대**할 수 있어요.
- 그래서 실제 서비스에서는 오래 걸리는 작업(DB 조회, 외부 API 호출 등)일수록 비동기 방식이 훨씬 유리해요.

## 2. 요청 파라미터 다루기 (`02_request_parameters/main.py`)

### 개념

URL 자체에 들어있는 값(Path)이나, `?뒤에=붙는값`(Query)을 받는 방법이에요.

```python
@app.get("/items/{item_id}")
async def read_item(item_id: Annotated[int, Path(ge=1, description="1 이상의 item ID")]) -> dict:
    return {"item_id": item_id}
```

- `item_id`는 **1 이상의 숫자만** 허용해요. 0이나 음수를 넣으면 FastAPI가 자동으로 거절해줘요.

### 고정 경로는 동적 경로보다 먼저!

```python
@app.get("/user/me")       # "me"라는 이름 전용 창구 (먼저 선언)
async def read_current_user(): ...

@app.get("/user/{user_id}")  # 그 외 모든 사용자 (나중에 선언)
async def read_user(user_id: str): ...
```

- 은행 창구를 생각하면, `/user/me`는 **"VIP 전용 창구"**고 `/user/{user_id}`는 **"일반 번호표 창구"**예요. VIP 전용 창구를 먼저 안내해야, "me"라는 이름의 손님이 일반 창구로 잘못 안내되는 일이 없어요. 순서를 반대로 하면 `/user/me` 요청이 `user_id="me"`로 처리돼버려서 의도한 대로 동작하지 않아요.

### 쿼리(Query)로 목록 필터링하기

```python
@app.get("/items", response_model=list[ItemResponse])
async def list_items(
    skip: Annotated[int, Query(ge=0)] = 0,
    limit: Annotated[int, Query(ge=1, le=10)] = 3,
    category: str | None = None
) -> list[ItemResponse]:
    filtered = [item for item in ITEMS if category is None or item.category == category]
    return filtered[skip : skip + limit]
```

- `?skip=2&limit=3&category=python`처럼 주소 뒤에 조건을 붙이면, 그 조건대로 목록을 걸러서(필터링) 원하는 만큼만(`skip`, `limit`) 잘라서 보여줘요. 쇼핑몰에서 "페이지 넘기기 + 카테고리 필터" 기능과 똑같은 원리예요.

## 3. 요청 Body 받기 (`03_request_body/main.py`)

### 개념

Path/Query는 "주소에 붙는 값"이라면, Body는 **"편지 봉투 안에 담긴 내용물(JSON)"**이에요. 회원가입 폼처럼 값이 많을 때는 Body로 받아요.

```python
class ItemCreate(BaseModel):
    name: str = Field(min_length=1, max_length=50)
    price: float = Field(gt=0)
    tax: float | None = Field(default=None, ge=0)

@app.post("/items")
async def create_item(item: ItemCreate) -> dict:
    return item.model_dump()  # Pydantic 객체 → 파이썬 딕셔너리로 변환
```

- Pydantic 모델(`ItemCreate`)로 타입을 미리 정해두면, FastAPI가 **"이 모양대로 온 JSON만 받겠다"**고 자동으로 검사해줘요.

### 여러 값 한 번에 받기

```python
@app.post("/users/{user_id}/items")
async def create_user_item(
    user_id: int,                                   # Path에서 옴
    item: ItemCreate,                                # Body 1
    user: UserInfo,                                  # Body 2
    importance: Annotated[int, Body(gt=0, le=5)]     # Body 3 (단일 값)
) -> dict:
    ...
```

- 재밌는 점은, FastAPI가 **함수에 적힌 타입 선언만 보고** "이건 Path에서 올 값, 이건 Body에서 올 값"을 알아서 구분해준다는 거예요. 우리가 "이건 Body예요"라고 일일이 표시 안 해도 돼요 (단, 단일 숫자값처럼 헷갈릴 수 있는 건 `Body(...)`로 명시).

## 4. 값 검증(Validation) 제대로 하기 (`04_validation/main.py`)

### 개념

Body를 그냥 `dict`로 받으면 **아무 검증도 안 해줘요.** 그래서 Pydantic 모델 + `Field` + `field_validator`를 조합해서 "이 값은 이래야만 정상"이라는 규칙을 만드는 법을 배웠어요.

```python
@app.post("/examples/raw")
async def accept_raw_json(payload: dict) -> dict:
    """dict만 사용하면 내부 필드의 타입, 범위, 필수 값을 자동 검증하지 않습니다."""
    return {"received": payload, "warning": "내부 필드 검증 없음"}
```

- 이건 "아무 검사 없이 다 받아주는 창구"예요. 비교를 위해 일부러 만들어둔 반례.

```python
class ProductCreate(BaseModel):
    model_config = ConfigDict(extra="forbid")  # 정의 안 된 필드가 오면 에러

    name: str = Field(min_length=2, max_length=50)
    price: float = Field(gt=0, le=1_000_000)
    category: Literal["book", "course", "tool"]  # 이 3개 중 하나만 허용
    tags: list[str] = Field(default_factory=list, max_length=5)

    @field_validator("name")
    @classmethod
    def normalize_name(cls, value: str) -> str:
        normalized = value.strip()
        if "무료" in normalized:
            raise ValueError("상품명에는 '무료'를 사용 할 수 없습니다.")
        return normalized
```

- `extra="forbid"`: 정해둔 필드 외에 다른 값이 섞여 오면 조용히 무시하지 않고 **에러로 딱 걸러낸다.** (오타나 잘못된 요청을 바로 알아챌 수 있음)
- `Literal["book", "course", "tool"]`: category는 이 세 단어 중 하나만 가능. 마치 드롭다운 메뉴처럼 **선택지를 제한**하는 것과 같아요.
- `@field_validator`: Field의 기본 규칙(길이, 범위)만으로 부족할 때, **직접 로직을 짜서** 검증할 수 있어요. 여기선 상품명에 "무료"라는 단어가 못 들어가게 막았어요.

### Path/Query에도 세밀한 제약 걸기

```python
@app.get("/search")
async def search(
    q: Annotated[str, Query(min_length=2, max_length=30, pattern=r"^[A-Za-z0-9가-힣]+$")]
) -> dict[str, str]:
    """검색어에 허용하지 않은 특수문자가 들어오면 422 Unprocessable Content 응답으로 거절"""
    return {"q": q}
```

- `pattern`(정규식)으로 "영문/숫자/한글만 허용"처럼 **특수문자·이모지 같은 이상한 입력을 원천 차단**할 수 있어요.

## 5. 응답과 에러 처리 (`05_response_and_errors/main.py`)

### 개념

API가 "뭘 돌려줄지"랑 "실패했을 때 뭐라고 말할지"를 깔끔하게 관리하는 법이에요.

### response_model로 민감정보 가리기 — 오늘 배운 것 중 제일 중요한 포인트

```python
users = {1: {"id": 1, "username": "teacher", "password": "internal-password", "display_name": "강사"}}

class UserResponse(BaseModel):
    id: int
    username: str
    display_name: str   # password는 여기 없음!

@app.get("/demo/unsafe-user", response_model=UserResponse)
async def unsafe_user() -> dict:
    return users[1]   # 원본엔 password가 있지만...
```

- 서버 내부 데이터(`users[1]`)에는 `password`가 들어있지만, `response_model=UserResponse`에 `password` 필드를 아예 빼놨기 때문에 **응답에는 password가 자동으로 걸러지고 안 나가요.**
- 이게 왜 중요하냐면, 코드 주석에도 적혀 있듯이 `response_model`을 안 쓰면 실수로 비밀번호나 내부 정보가 그대로 API 응답에 노출될 수 있어요. **"보여줄 것만 정확히 정의해두는 습관"**이 보안에서 진짜 중요해요.

### 404 에러를 깔끔하게 처리하는 공통 함수

```python
def find_user_or_404(user_id: int) -> dict:
    user = users.get(user_id)
    if user is None:
        raise HTTPException(status_code=404, detail="사용자를 찾을 수 없습니다.")
    return user
```

- "사용자를 찾고, 없으면 404 에러 던지기"를 매번 반복해서 쓰지 않도록 **함수 하나로 묶어둔 것.** 여러 API에서 재사용할 수 있어요.

### 응답에 헤더 추가하기

```python
@app.get("/users", response_model=list[UserResponse])
async def list_users(response: Response) -> list[dict]:
    response.headers["X-Total-Count"] = str(len(users))
    return list(users.values())
```

- 몸통(응답 데이터) 말고 **택배 송장에 적는 부가 정보(헤더)**처럼, "전체 몇 명인지(X-Total-Count)" 같은 정보를 헤더에 따로 실어 보낼 수 있어요. 실제 페이지네이션 API에서 자주 쓰는 패턴이에요.
