## 1. 쉘과 커널

- **커널**: OS의 진짜 핵심. 하드웨어(CPU, 메모리 등)와 소프트웨어 사이의 통신, 자원 관리를 전담한다.
- **쉘**: 우리가 직접 만지는 부분. 사용자가 입력한 명령을 해석해서 커널에 전달해주는 "통역사" 역할이다.
- `echo $SHELL`로 지금 사용 중인 쉘이 뭔지 확인할 수 있고, `cat /etc/shells`로 시스템에 설치된(변경 가능한) 쉘 목록을 볼 수 있다.
- `sh`를 입력하면 배쉬(bash)를 열어 터미널로 사용할 수 있다.

---

## 2. 권한 전환

```bash
sudo su   # 관리자(root) 권한으로 전환
exit      # 원래 계정으로 돌아오기
su        # 다른 사용자(주로 관리자) 권한 획득
```
- `su`는 아예 사용자를 바꿔서 로그인하는 느낌이고, `sudo`는 지금 내 계정 그대로 "이 명령어 하나만 관리자 권한으로 실행해줘"라고 요청하는 방식이다.

## 3. 패키지 관리 (apt)

```bash
sudo apt install <패키지명> [<패키지명> ...]   # 여러 개 한 번에 설치 가능
sudo apt install curl
sudo apt remove <패키지명>                      # 삭제
sudo apt autoremove                             # 더 이상 필요없는 패키지 정리
sudo apt update                                 # 패키지 목록을 최신화
apt search curl                                 # 패키지 검색
apt list                                        # 설치된 패키지 목록 확인
apt list | tail                                 # 목록 마지막 부분(약 10개)만 확인
```
- **curl**: 리눅스에서 특정 URL(API 엔드포인트 등)이 실제로 응답하는지 테스트하는 도구. `curl --version`으로 설치 여부를 확인할 수 있다.
- 참고로 Swagger 문서에서 각 API에 "curl" 예시가 붙어 있으면, 그 요청이 실제로 정상 작동할지 바로 확인해볼 수 있다는 의미로 이해하면 된다.

## 5. 텍스트 편집기 — vi/vim

```bash
sudo apt install vim
apt list --installed | grep '^vim'   # vim이 설치돼 있는지 확인
```
- vi는 유닉스 환경의 기본 텍스트 편집기이고, **nano**나 **vim**(플러그인 지원)처럼 개선된 버전들이 있다.
- **입력 모드로 전환**: `i`(현재 위치에서 입력), `a`(다음 칸부터 입력), `o`(새 줄 만들고 입력), `s`(글자 지우고 입력) 등.
- **커서 이동**: `h`(왼쪽), `l`(오른쪽) 등 방향키 대신 문자로 이동.
- **종료**: `:q` (그냥 종료, 저장 안 함).

> 참고로 최근 git 머지 작업 때 만났던 Vim 커밋 메시지 화면도 결국 이 vi 계열 편집기였다 — `i`로 입력모드 진입, `Esc`로 빠져나온 뒤 `:wq`로 저장 후 종료하는 방식이 오늘 배운 것과 그대로 이어진다.

## 6. 리눅스 파일 시스템 구조

- 리눅스는 Windows처럼 `C:\`, `D:\`가 따로 있는 게 아니라, **최상위 `/`(루트) 아래에 모든 폴더가 매달려 있는 구조**다.
- Windows의 `Program Files` 폴더처럼, 프로그램 관련 파일들이 특정 규칙에 따라 정해진 위치에 저장된다고 이해하면 된다.

## 8. Docker 입문

### VM(가상머신) vs Docker
- **VM 방식**: VirtualBox 같은 프로그램으로 실제 하드웨어(CPU/RAM)를 나눠서, 그 위에 **완전한 가상 PC(운영체제 통째로)**를 하나 더 띄우는 방식이다. 가상 PC 하나에 보통 2~4GB, 넉넉히 쓰려면 8GB 정도는 필요하다는 이야기가 나왔다.
- **Docker 방식**: 운영체제 전체를 새로 띄우지 않고, **이미지 하나만 있으면 그 안에 필요한 실행 환경을 훨씬 가볍게 구성해서 운영**할 수 있다.

### 이미지 vs 컨테이너
- **이미지**: 서비스 운영에 필요한 서버 프로그램(설계도)
- **컨테이너**: 그 이미지를 실제로 실행한 상태. 소스코드, 라이브러리, 컴파일된 실행 파일을 하나로 묶어서 격리된 환경에서 돌린다.

### 쿠버네티스 & 스케일링
- **쿠버네티스**: 똑같은 이미지로 컨테이너를 여러 개(a, b, c...) 만들어서 관리해주는 도구.
- **스케일 아웃**: 컨테이너 개수를 수평으로 늘리는 것 (서버를 여러 대로 분산).
- **스케일 업**: 컨테이너 하나의 CPU·메모리 등 자원을 수직으로 늘리는 것.

### 설치 환경 관련
- Windows Pro 사용자는 Hyper-V 기반 가상화로도 Docker Engine을 쓸 수 있지만, Home 에디션과 공통으로 쓸 수 있는 **WSL2 방식**으로 통일해서 설치를 진행했다.
- **Docker Desktop**을 설치하면 GUI로 이미지/컨테이너를 관리할 수 있다.
- **볼륨(Volume)**: 컨테이너 안에서 생긴 데이터는 원래 컨테이너를 지우면 같이 사라지는데, 볼륨을 사용하면 컨테이너를 삭제해도 데이터를 남겨둘 수 있다 — "언제 볼륨을 쓰냐"는 질문의 답이 바로 이 저장(영속성) 때문이다.

### 실습한 Docker 명령어
```bash
docker images                                   # 보유한 이미지 목록
docker run hello-world                          # hello-world 이미지 실행(테스트)
docker pull hello-world                         # 이미지 다운로드
docker ps                                        # 실행 중인 컨테이너 목록
docker ps -a                                     # 종료된 것까지 전체 컨테이너 목록

docker run --name hi hello-world
# hello-world 이미지로 실행하되, 컨테이너 이름을 'hi'로 지정

docker container run -d --name ubuntu_test ubuntu
# -d : 백그라운드(데몬)로 실행

docker container run -it --name ubuntu_test2 ubuntu
# -it : 컨테이너 내부 터미널에 직접 들어가서 사용
```

## 오늘의 핵심 정리

1. 쉘은 사용자와 커널을 이어주는 중간 계층이고, 커널이 하드웨어를 실제로 관리한다.
2. 우분투 계열에서는 `apt`로 패키지를 설치·삭제·검색·업데이트한다.
3. vi/vim은 입력 모드(`i`, `a`, `o`, `s`)와 명령 모드를 오가며 사용하고, `:wq`로 저장 후 종료한다 — 이건 최근 git 머지 커밋 때도 그대로 써먹었다.
4. 리눅스는 `/` 하나의 루트 아래 모든 파일이 계층 구조로 존재한다.
5. Docker는 VM처럼 OS 전체를 새로 띄우지 않고, 이미지 하나로 가볍게 실행 환경을 구성한다 — **이미지(설계도) → 컨테이너(실행된 상태)** 흐름을 기억하면 된다.
6. 컨테이너는 지우면 데이터도 같이 사라지는 게 기본이라, 데이터를 남기고 싶으면 볼륨을 써야 한다.
